## 🎁 실무진이 환호하는 멤버십 & 유저 활성화(Retention) 관리 기능

### 1. 출석체크 기반 포인트 전환 및 광고 제거(Ad-Block) 권한 동적 제어

> **실무진의 고민:** 유저의 재방문율(Retention)을 높이기 위해 출석 보상 시스템을 도입하지만, 단순 포인트 지급만으로는 유저에게 강력한 유료화 모델(BM)의 가치를 체안하기 어렵습니다. 또한, 기간제 유료 권한을 매번 RDB로 조회하면 트래픽이 몰릴 때 데이터베이스 부하가 극심해집니다.

* **아이디어:** 출석 체크로 모은 포인트를 활용해 유저가 '광고 제거 7일권'을 구독할 수 있는 시스템입니다. RDB의 부하를 최소화하면서 대규모 트래픽에서도 실시간으로 유저의 광고 제거 권한을 동적으로 제어합니다.
* **API 및 기술적 구현:**
* **Redis TTL 기반 권한 관리:** 유저가 광고 제거권을 구매하는 즉시 Redis에 `Key: "user:ad_block:user_id" / Value: true` 형태로 만료 시간(TTL)을 7일 설정하여 저장합니다.
* **Security Filter & Context Injection:** 백엔드(Spring Security / NestJS Guard 등)로 들어오는 모든 API 요청의 길목에서 Redis 값을 먼저 조회합니다. 값이 존재하면 유저 인증 객체에 `is_ad_blocked=true` 상태를 동적으로 주입하여 RDB 조회 없이 권한을 검증합니다.
* **React 동적 컴포넌트 렌더링:** 프론트엔드는 API 응답에 포함된 유저 상태를 바탕으로 구글 애드센스나 사내 광고 배너 컴포넌트를 완전히 숨기거나 노출하는 조건부 렌더링을 수행합니다.


* **풀스택 어필 포인트:** 단순한 포인트 적립 기능을 넘어, 고성능 인메모리 데이터베이스(Redis)의 특성을 활용해 "대규모 트래픽 환경에서 인프라 비용을 아끼며 실시간 권한을 제어하는 아키텍처"를 백엔드와 프론트엔드 전반에서 매끄럽게 풀어낸 경험을 증명합니다.
* **면접관이 열광하는 이유:** 서비스 유료화(BM)의 핵심인 '기간제 기능 제한/해제' 문제를 가장 실무적이고 확장성(Scalability) 높은 기술 스택으로 해결했기 때문입니다.

### 2. 등급별(VVIP) 가치 제안: 개인화된 특별 모임 추천 및 타겟팅 쿠폰 발급 시스템

> **실무진의 고민:** 플랫폼의 매출을 리드하는 핵심 고기여 유저(VVIP)를 락인(Lock-in)하기 위해서는 차별화된 UX와 혜택을 제공해야 합니다. 하지만 등급 변경 시 권한이 실시간으로 동기화되지  않거나, 등급별 노출 로직이 꼬이면 유저 경험이 크게 저하됩니다.

* **아이디어:** 일반 유저와 VVIP 유저의 화면을 차별화하여 충성심을 고취시키는 관리 시스템입니다. 등급 상승 시 실시간으로 권한을 갱신하고, VVIP 전용 시크릿 모임 추천 및 무료 참여 쿠폰을 타겟팅하여 발급합니다.
* **API 및 기술적 구현:**
* **실시간 권한 갱신 (JWT & Redis):** 유저가 특정 조건을 만족해 VVIP 등급이 되거나 쿠폰을 활성화하면, 백엔드에서 세션 상태(또는 Redis 내 유저 권한 토큰)를 즉시 업데이트합니다.
* **커스텀 쿼리 및 필터링 (JPA @Query):** RDB 조회 시 커스텀 쿼리를 활용해 `where is_vvip_only = true` 조건이 걸린 프리미엄 모임 리스트를 효율적으로 추출합니다.
* **React UX (Blur & Lock):** 프론트엔드에서는 일반 유저에게 VVIP 전용 콘텐츠를 블러(Blur) 처리나 자물쇠 아이콘으로 시각적 제한을 두고, 등급이 충족되면 부드러운 애니메이션과 함께 시크릿 리스트가 활성화되도록 구현합니다.


* **풀스택 어필 포인트:** 플랫폼 비즈니스의 핵심인 **'유저 등급별 서비스 차별화 정책'을 백엔드 DB 구조(1:N 관계 및 효율적인 인덱싱 쿼리)부터 프론트엔드 UI/UX 예외 처리까지** 일관성 있게 연결해 본 깊이 있는 구현 역량을 보여줍니다.
* **면접관이 열광하는 이유:** 유저 데이터 권한(Role-Based Access Control) 관리가 단순한 페이지 접근 차단을 넘어, 플랫폼의 핵심 비즈니스 로직 및 마케팅 전략과 어떻게 맞물려 돌아가는지 정확히 이해하고 있기 때문입니다.

### 3. 노쇼(No-Show) 방지를 위한 멤버 신뢰도 레포팅 및 패널티 관리 시스템

> **실무진의 고민:** 모임 및 행사 플랫폼에서 '신청 후 무단 불참(노쇼)'은 모임의 질을 떨어뜨리고 다른 유저의 참여 기회를 박탈하는 가장 치명적인 비즈니스 리스크입니다. 수동 제재는 한계가 있으므로, 데이터 기반의 자동화된 패널티 시스템이 필수적입니다.

* **아이디어:** 유저의 예약 이행률을 데이터화하여 '신뢰도 점수(매너 온도)'를 운영하고, 노쇼 발생 시 자동으로 패널티를 부과하여 악성 유저의 활동을 시스템적으로 제약하는 백오피스 및 회원 관리 기능입니다.
* **API 및 기술적 구현:**
* **신뢰도 스코어링 시스템:** 회원 테이블(`User`)에 `trust_score` 필드를 두고 기본 100점을 부여합니다. 모임 참석 완료 시 +2점, 무단 불참(노쇼) 시 -10점을 차감하는 비즈니스 로직을 구축합니다.
* **자동 상태 변경 스케줄러 & Validation:** 스코어가 70점 이하로 떨어지면 유저의 상태(`User_Status`)를 `RESTRICTED`로 자동 전환합니다. 이후 유저가인기 모임 신청 API를 호출할 때, 백엔드 검증 레이어(Validation)에서 이를 차단하고 커스텀 에러 코드를 반환합니다.
* **React 방어적 컴포넌트 설계:** 프론트엔드에서는 해당 유저의 대시보드에 신뢰 점수 하락 경고 그래프를 보여주고, 모임 신청 버튼 자체를 비활성화(Disabled) 처리하여 불필요한 API 요청을 프론트 단에서 1차적으로 방어합니다.


* **풀스택 어필 포인트:** 기술 자체의 화려함보다 **"실제 서비스를 운영할 때 발생하는 정성적인 비즈니스 리스크(노쇼)"를 데이터(Score)와 시스템 검증(Validation)이라는 공학적 접근법으로 우아하게 해결한 경험**을 강조합니다.
* **면접관이 열광하는 이유:** 운영 효율화와 플랫폼 생태계 보호는 시니어 개발자들도 항상 고민하는 영역입니다. 주니어 레벨에서 이러한 '비즈니스 리스크 방어 로직'을 멤버 관리 시스템에 녹여냈다는 점 자체에 크게 환호할 것입니다.

create table members(
    member_id number primary key,
    login_id varchar2(50) unique not null,
    mobile varchar2(20) unique not null,
    nickname varchar2(50) unique not null,
    email varchar2(100) unique not null,
    password varchar2(255) unique not null,
    profile_url varchar2(500),
    member_type_id number not null,
    status_id number not null,
    created_at date default sysdate not null,
    update_at date default sysdate not null,
    delete_yn char(1) default 'N' not null,

    constraint fk_member_type
        foreign key(member_type_id)
        references member_type(member_type_id),

    constraint fk_member_status
        foreign key(status_id)
        references member_status(status_id)
);
